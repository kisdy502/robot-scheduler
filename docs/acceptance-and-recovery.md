# 验收计划与重启恢复

## 一、职责边界

调度负责：移动、任务状态、交通占用、机器人使用权。业务动作（质检/充电启动）、检测结果、报告归上层服务。
测试报告记录调度验收结果，不是产品质检报告。目标版本：单实例、单楼层、业务已指定机器人。

## 二、新版业务流联调顺序（2026-11 定稿）

| 步骤 | 调用 | 通过条件 |
|---|---|---|
| 1. 抢占 | POST /assign-task（taskflow 雪花整数 + robot_code） | 成功；/robot-use 显示持有者 |
| 2. 移动 | POST /goto-place（task_id = 雪花+时间戳，幂等可选） | task_status=completed，位置符合业务精度 |
| 3. 业务动作 | **上层直连 RMS start-activity**（模板需本体已预置；充电 activity=模板 code） | RMS 受理 |
| 4. 读结果 | GET /observability/activities?task_id= | action_status=3 + result_report；非 3 看 failure_msg |
| 5. 释放 | POST /release-robot | 使用权清空（物理驻留保留） |

取消兼容语义：活动任务取消可能表现为 completed + cancellation——上层必须检查 `data.raw.task_state.cancellation`，不能只看 completed。

> 旧接入模式（external-operations start/finish 通知）仍可用，见 history/robot-ownership-external-operations.md；新业务流推荐上面五步。

## 三、代码回归覆盖

`ThirtyRobotWorkflowTest`（真实内核 + 隔离 RMS 模拟）：30 台 × 10 轮业务闭环（取得使用权→移动→外部作业→移动→释放），300 闭环/600 次移动全收口。
当前全量 **349 用例**（2026-11-04 后含外部动作镜像/stop 幂等/goto-place 契约回归）。
模拟不含真实 HTTP 延迟、DB 写入、轮询帧滞后、车体尺寸——通过≠实车稳定。

## 四、持久化运行正本（t_robot_runtime）

每台机器人保存：使用权、外部作业、路线预约、实际驻留、停止确认状态、地图版本、执行任务 ID、命令序号。

**写入纪律**：使用权/占用变更**先提交 DB 事务再改内存**；写失败不确认新预约（HTTP 503）；释放失败继续冻结旧资源由停止确认收口；命令序号下发前提交、只增不减。

**重启行为**：

| 重启前状态 | 恢复处理 |
|---|---|
| 已取得使用权，未提交移动 | 恢复持有者，不自动产生任务 |
| 进行中外部作业 | 恢复原 operation_id 保持忙碌，不自动 finish |
| 未完成导航预约 | 恢复全部点段 → 等待停止确认，**不自动重放导航** |
| 只有驻留 | 恢复物理障碍，不释放 |
| 机器人离线 | 不因时间流逝清空占用 |

任务状态：未终态任务标 failed 不重跑；上层先查状态再决定接续或新 task_id 重做。

**地图恢复**：恢复占用必须对应原地图名+版本；不一致**停止启动**（不回退无图模式）。换图标准操作 = 换 local-map + `TRUNCATE t_robot_runtime` + 重启。

**首次升级/换版**：停上层派发 → 确认在途机器人停止 → 完整停旧进程 → 备份 DB → 新版启动（Flyway 自动迁移）→ 恢复使用权登记 → 恢复派发。单活部署，滚动发布禁止新旧实例重叠。

## 五、分阶段验收门槛

| 阶段 | 场景 | 要点 |
|---|---|---|
| A | 单台十轮真实闭环 | 移动/业务动作/释放全关联，无误到点/重复执行 |
| B | 5 台共享作业点 | 有序排队，离场后继续 |
| C | 30 台各自工位十轮 | 300 闭环无丢失/残留 |
| D | 共享交叉口 | 实测无冲突，阻塞解除后恢复 |
| E | 异常注入 | 网络超时/重复请求/一台离线/取消；其余车辆不受影响 |
| F | 持续 8h+ | 内存/队列/连接池无增长，任务全收口 |
| G | 重启恢复 | 在途导航/外部作业恢复正确，停止确认前不发新导航 |

建议记录：受理 P50/P95、状态帧间隔、等待耗时、失败原因分布、RMS 命令量、DB 写耗时、资源占用。
参考线：受理 P95 < 1s、状态帧 < 5s。
