# 交通管制手册（占用模型 · 冲突场景 · 异常恢复）

## 一、占用模型（三级）

| 层级 | 含义 | 产生 | 释放 |
|---|---|---|---|
| 活动租约（段+途经点） | 在途任务对前方路线的独占 | tryAcquire（**途经点全量持有**——防他人把我的途经点当目标汇合相撞） | releaseBehind 身后渐进 + releaseAllAndDwell 终态原子 |
| 驻留点 | 静止机器人的物理占点（0.8m 阈值吸附） | FleetManager 每帧 updateDwell | 机器人移动即清除/接续新驻留 |
| 驻留段 | 静止机器人的占段（停在两点之间） | 同上（段吸附 1m） | 同上 |

**核心不变量**：在线机器人必然占一个点或一段；每机器人至多一个在途命令；到达即驻留原子接管。

**交通等待语义**：目标/路径被占 → 任务排队，**8s 间隔发 TRAFFIC_WAIT 事件**（保持任务事件流活跃防 stale 误判），等待上限 300s 超时失败。

## 三、异常后的占用保留（停止确认）

导航失败/超时、执行中取消、失联时：**冻结剩余路线预约与最后驻留** → 下发 stop → 确认后原子转实际驻留。

**stop 幂等契约**（2026-11-03 定稿）：
- `NO_ACTIVE_TASK`（无活动任务）→ 幂等成功
- `BODY_STOP_TASK_REJECTED + reject_reason 含 "already"`（本体任务已终态，无可停之物）→ **幂等成功**
- 其他拒绝保持三态映射重试（5s 间隔）
- 若不识别 "already"，会陷入 5s 重发 stop 死循环：交通占用永久保留 + 机器人不可派发（真机事故教训）

确认条件：stop 已接受（含上述幂等）+ 无本地待回执命令 + 地图匹配可吸附 + 连续 3 帧位置 5cm/朝向 0.1rad 稳定。确认期间不可新导航、不可切图。

## 四、死锁两场景

**死端必经点被驻留**：B 静止堵住唯一通路 → A 规划无路 → 持续等待 → B 移动后自动恢复。300s 上限兜底失败。
**对向互换单线**：统一段 ID 互斥，先占先得，后到者排队到先到者通过释放。

循环等待（A 等 B、B 等 A）由 DeadlockMonitor 检出告警；当前**不自动让路**（升级候选：让路点导航，见 rmf-traffic-analysis.md P2/P3）。

## 五、交通审计存储

- `DbTrafficEventSink`：resource_id 保存一次事件的完整资源列表（逗号拼接，可超 128 字符）→ **V10 扩为 TEXT**（旧 VARCHAR(128) 插入失败已修复）
- 持久化占用成功后才发审计事件；审计失败隔离告警，不撤回已提交占用
- 已丢历史审计不自动补回；部署含 V10 版本由 Flyway 自动升级，重启前确认无在途任务
